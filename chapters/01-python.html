  11. 知识点集合

    收录对话中学过、讨论过或主动问过的内容，不区分掌握或待复习。点击标题展开。

    对象、引用与赋值（M01-Q01）
    • 变量保存的是对象引用；直接赋值会让两个名称指向同一对象，而不是复制对象。
    • 通过任一引用原地修改可变对象，其他引用都能观察到变化；给局部变量重新赋值只会改变该名称的指向。
    • == 比较值，is 比较对象身份；值相等不保证是同一个对象。
    可变对象、不可变对象与函数参数（M01-Q01）
    • 列表、字典等可变对象可被原地修改；整数、字符串等不可变对象的“修改”会创建或引用另一个值。
    • Python 函数传递对象引用：修改参数指向的可变对象会影响调用方，重新绑定参数不会。
    • 运行时对象、内存引用和磁盘持久化字节是不同层次，不能用磁盘存储直接解释对象可变性。
    默认可变参数与 None 哨兵（M01-Q01）
    • 函数默认参数在函数定义时创建一次；默认列表会被多次调用共同复用并累积内容。
    • 需要每次调用创建新容器时，以 None 为默认值，在函数内用 is None 判断后创建。
    • 调用方显式传入的容器是另一个对象，不会与函数的默认容器混在一起。
    浅拷贝与深拷贝（M01-Q01）
    • 浅拷贝创建新的外层容器，但嵌套的可变对象仍与原对象共享。
    • 深拷贝递归复制嵌套对象，使嵌套修改通常相互隔离，但成本更高且并非任何对象都适合复制。
    • 判断拷贝影响时，应逐层检查对象身份和修改发生在哪一层。
    进程、线程、协程与身份（M01-Q08）
    • 进程拥有独立地址空间并由操作系统调度；线程共享进程内存，也由操作系统调度；协程由事件循环协作调度。
    • 同一进程内线程的 PID 相同、线程 ID 不同；同一线程内协程的 PID 和线程 ID 都相同。
    • CPU 密集任务通常用多进程，阻塞式 I/O 可用线程，大量支持异步的 I/O 可用 asyncio。
    GIL、事件循环与 await（M01-Q08）
    • GIL 与事件循环是不同层次：GIL 约束 CPython 线程执行 Python 字节码，事件循环调度协程。
    • await 不会创建线程；协程只在 await 等让权点把控制权交回事件循环。
    • time.sleep 会同步阻塞承载事件循环的线程；异步代码应使用 await asyncio.sleep(...) 或把阻塞工作卸载到线程。
    异步超时、取消与清理顺序（M01-Q08）
    • 没有让权点的纯 Python 计算会占住事件循环，超时计时虽然开始，却无法准时执行取消。
    • 取消通常在协程到达可取消的 await 时以 CancelledError 进入。
    • asyncio.wait_for 会等待被取消任务执行 finally 清理，然后再向调用方抛出 TimeoutError。
    共享状态、竞态与锁（M01-Q08）
    • 各协程的局部变量保存在各自执行帧中，但它们仍可能共享模块级或容器对象。
    • 多个协程读取同一旧值、让权后再写回，会造成丢失更新。
    • asyncio.Lock 能串行保护临界区，但会带来等待和锁竞争；能让任务返回独立结果并用 gather、sum 汇总时，优先避免共享状态。
    函数作用域与 global（M01-Q08）
    • 函数体内只要对某名称赋值，该名称默认在整个函数体中按局部变量解析。
    • 在赋值前读取该局部名称会触发 UnboundLocalError，即使模块级存在同名变量。
    • global 可以声明模块级绑定，但减少共享可变状态通常更清晰。
    可维护性、边界与副作用（M01-Q10）
    • 名称应表达业务含义，函数职责应小而明确；纯判断与修改列表等副作用应分开。
    • 返回布尔值不是副作用；修改调用方容器、全局状态或执行 I/O 才是可观察副作用。
    • 缺失字典键会产生 KeyError；未捕获异常会中断正常流程并沿调用栈传播，匹配的 except 处理后才会继续。
    • 测试应分别验证返回值和状态变化。性能选择要测量：高频成员检查适合集合，单次检查可能不值得承担集合构建时间和额外内存。
    生成器、yield 与单次消费（M01-Q03）
    • 调用含 yield 的函数只创建生成器对象；首次 next 才执行函数体，生成器会保存暂停位置和局部状态。
    • yield 的动作可以记为“交出一个值并暂停”：一次 next 只执行到下一个 yield，其后的代码要等再次调用 next 才继续；return 则结束函数。
    • 在循环中直接 yield 当前元素即可逐项生成；先用 append 建立完整列表再 return 是普通容器实现，不具备惰性生成的内存特征；改成 yield 后应删除未使用的结果列表。
    • yield 把值交给调用方，本身不会在屏幕打印；是否显示取决于外层 print。
    • 函数结束后生成器耗尽并抛出 StopIteration；next(generator, default) 在耗尽时返回默认值。
    • 单次消费针对同一个生成器对象：它只保存当前位置而不保存可倒带的完整历史，耗尽后处于关闭状态；再次调用生成器函数可创建一个从头开始的新生成器对象。是否换变量名不重要，重新调用函数才是关键。
    • 生成器通常是单次消费的惰性序列；它可降低一次性内存占用，但执行路径和调试比已物化容器更隐蔽。
    装饰器、上下文管理器与描述符的职责（M01-Q04）
    • 装饰器用于给函数统一增加计时、日志等行为；@decorate 等价于定义原函数后执行 func = decorate(func)。
    • 上下文管理器管理资源生命周期，例如数据库连接在正常结束或异常离开时执行清理；描述符用于控制属性读取和赋值，例如禁止 age 为负数。
    • 装饰器返回 wrapper 函数对象供以后调用；return wrapper() 会立即执行包装函数并返回其结果，若结果为 None，装饰后的名称将不再可调用。
    • 包装函数依次执行前置行为、原函数、后置行为；普通后置语句在原函数抛异常时不会执行，必须清理的工作应使用 finally 或上下文管理器。
    参数收集、拆包与匹配（M01-Q04）
    • 函数定义中的 *args 将剩余位置参数收集成元组，**kwargs 将未被明确参数名接收的关键字参数收集成字典；名称可以更换，星号决定行为。
    • 零个剩余位置参数得到 ()，一个得到 (value,)，多个按顺序进入元组；普通参数先按位置匹配，关键字参数按名字匹配，不应理解为按 first、kwargs、args 顺序执行收集。
    • 函数调用中的 *iterable 将可迭代对象拆成位置参数，支持列表、元组、字符串、生成器等；对字典使用一个星号得到键。
    • 调用中的 **mapping 将映射拆成关键字参数，键必须为字符串且参数必须被函数接受。字典顺序不影响按名匹配；额外参数可以由定义中的 **kwargs 接收。
    • func(args, kwargs) 传入两个完整容器；func(*args, **kwargs) 转发其中的参数。例如 args=(2,3)、kwargs={} 时，前者等价于 func((2,3), {})，后者等价于 func(2,3)。
    • 拆包只处理最外层，嵌套字典仍作为原对象传入；需要拆内层时明确使用 func(**data["profile"])，拆包不会复制嵌套对象。
    • 缺少必需参数、参数无人接收或同一参数同时通过位置和关键字重复赋值会报 TypeError。普通位置参数不能直接放在关键字参数后；Python 代码须使用英文标点。
    元组、列表与嵌套可变对象（M01-Q02 / M01-Q04）
    • 列表和元组都支持多个元素、顺序遍历与下标访问；列表允许增删或替换元素，元组的长度和各位置引用不可修改。元组没有只能装两个元素的限制。
    • (20,) 是单元素元组，(20) 是整数；*args 收集成元组属于 Python 语法规定。
    • 元组内引用的列表仍可原地修改：data=([1,2],3) 时 data[0].append(4) 成功，data[1]=5 抛 TypeError。需要调整元素使用列表，需要固定一组位置引用可使用元组。
    函数对象、计算结果与返回值传递（M01-Q04）
    • return func 返回函数对象；return func(...) 调用函数并返回计算结果。输入参数、函数对象和返回结果是不同对象。
    • 函数正常结束而没有执行带值的 return 时返回 None；调用内层函数不会自动把其返回值作为外层返回值。
    • value = inner(); return value 与 return inner() 都能传递内层返回值。若 inner 返回 5，两者都返回 5；包装函数仅执行 func(...) 而不 return 时会丢失返回值。
    装饰器名称替换与重复调用陷阱（M01-Q04）
    • 装饰器不复制原函数：定义原 add 后，add = decorate(add) 调用 decorate，将它返回的 wrapper 绑定到 add；wrapper 通过闭包中的 func 保留原 add 的引用。调用 add(2,3) 实际进入 wrapper，*args 接收两个值并转发给原 add。
    • 先 func(*args, **kwargs) 再 return func() 会调用原函数两次；第二次没有参数时可能因缺少必需参数抛 TypeError，第一次返回值已经被丢弃。应直接 return func(*args, **kwargs)，或保存第一次结果再 return。
    调用参数、函数对象与包装层边界（M01-Q04）
    • 每次调用都须明确提供参数，func() 不会记住上次 func(2,3) 的实参；args、kwargs 容器可重复转发，但生成器等单次消费对象可能耗尽。
    • 返回函数对象并非返回源码文本；打印对象通常得到形如 <function number at 0x...> 的表示，地址因运行而异，调用返回的对象才执行函数体。
    • decorate(func) 收到一个函数对象，无需与原函数参数数量一致；wrapper 收到业务实参，转发给原函数时必须符合原函数签名。wrapper 内的 args、kwargs 不会自动成为 decorate 的局部变量。
    • 仅转发参数和返回值的装饰器用于教学，业务中通常没有新增价值；加入日志或计时等统一行为才体现包装目的。return func(...) 应在 wrapper 内，decorate 自身返回 wrapper 对象。
    装饰时传函数，调用时传数据（M01-Q04）
    • 函数也是可作为参数传递的对象：decorate(add) 把原 add 对象作为一个实参交给 func，此时既不执行 add，也不提供 a、b。
    • 装饰阶段可展开为 original_add=add、wrapped_add=decorate(original_add)、add=wrapped_add；调用阶段 add(2,3) 进入 wrapper，收集 args=(2,3)、kwargs={}，再调用闭包保留的 original_add(2,3)。
    • 被传入的对象自身如何调用，与接收该对象的函数需要几个参数是两件事；如 inspect_function(add) 可以只接收函数对象，不必接收 add 的两个业务参数。
    装饰器统一附加行为的用途（M01-Q04）
    • 多个业务函数需要相同日志、计时或权限检查时，装饰器把共同逻辑集中一处，避免在每个函数内重复维护，同时保留各自的业务参数和返回值。
    • func.__name__ 可读取原函数名称供日志使用。只有一个简单函数时直接写附加逻辑可能更清晰，无需为了使用装饰器而包装。
    包装函数误调用自身（M01-Q04）
    • wrapper 内调用 wrapper(*args, **kwargs) 会再次进入同一个包装函数，不断递归，最终触发 RecursionError；应调用闭包中保存的原函数 func(*args, **kwargs)，并返回其结果。
